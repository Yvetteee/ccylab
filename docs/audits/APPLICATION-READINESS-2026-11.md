## Minimum remaining activation plan

1. **Approve routing and data handling.** The lab owner and institutional mailbox owner approve the Production and optional fallback destinations, who can access attachments, permitted providers, retention/deletion and the privacy notice. Identify Cloudflare Worker and Turnstile administrators, a Resend administrator, a Vercel release operator and a mailbox verifier. Include the Squarespace DNS administrator only if sender verification needs new records. Record a separate activation authorization.
2. **Recover configuration and isolate test traffic.** With authenticated read access, identify Worker version, deployment environment, origins, rate bindings and secret names. Confirm the Turnstile widget modes, hostnames and key pairing, and Resend's sending domain, approved From address, key scope and any historic delivery metadata. Use distinct Worker environments and credentials. Restrict the test Preview and Worker to the approved test path. Configure Production for the official www origin and agreed institutional mailbox. Set only public form configuration in the corresponding Vercel targets.
3. **Accept the exact configuration in isolation.** Run a synthetic PhD application with intake and a synthetic Postdoc application without intake. Include a small PDF and one near the final limit across the two cases. Verify both browser outcomes, provider event, correct mailbox, attachment integrity, sender and Reply-To. Check wrong origin, invalid fields/file or size, missing/invalid/expired Turnstile, rate-limit responses, temporary provider failure and a retry. A retry needs a fresh Turnstile token and the same logical submission ID. Confirm one received message for the same payload and key, generic client errors and no unnecessary sensitive logging. Keep all test-recipient traffic isolated from the public.
4. **Stage, promote, verify and retain rollback.** Record the known Production deployment and configuration. Stage a Production Vercel build with the approved settings using `vercel deploy --prod --skip-domain`. Check the staged document, scoped build configuration, CSP, application noindex and public-site indexing. Verify the Production Worker accepts an OPTIONS preflight from the exact www origin and rejects obsolete Preview origins. Keep synthetic deliveries in the isolated environment until the official-origin and approved-recipient checks can run. Promote the exact staged deployment. Verify the links, widget and approved fallback on www, then make one separately authorized synthetic delivery to the institutional intake mailbox. If a critical check fails, restore the indexed pre-activation deployment `dpl_A7rMVanqRS8UJBn7eUWDBG3qKu7h`, stop public Worker intake using its separately authorized configuration rollback, and verify disabled forms, canonical routing and indexing.

The implementation and local suite are reusable. Handle the production-specific gaps before deciding whether activation is configuration-only. The Worker currently checks declared request length above 21 MiB before parsing and validates the first `pdf` part. Enforce a real aggregate body cap through the platform or a bounded parser if the platform cannot provide one. If acceptance requires exactly one multipart PDF part, reject duplicates in the Worker. Add explicit failure handling for missing origin configuration where needed. Keep any source change focused on a failed safety or acceptance gate.
