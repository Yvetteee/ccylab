### Blocking controller checks

- The checked code uses a header-only early size check, then calls `request.formData()`. Its final file size check occurs after multipart parsing. The standard Cloudflare zone request ceilings start above the intended 21 MiB cap. The documented actual-body WAF field requires Enterprise, and no equivalent rule on the historical endpoint has been established. If the account has no verified equivalent, add a small byte-counting stream before the existing multipart parser, cancel on overflow, return the existing safe `file_too_large` code, and validate one `pdf` part. Keep the 20 MiB PDF cap. [Cloudflare limits](https://developers.cloudflare.com/workers/platform/limits/) · [WAF body-size field](https://developers.cloudflare.com/ruleset-engine/rules-language/fields/reference/http.request.body.size/)
- Siteverify currently checks `success` only. Require its returned hostname to equal the environment's expected hostname. If an action is configured on the widget, verify that action too. Missing origin or hostname configuration should fail closed. Keep any patch within the Worker and add focused regression checks. [Siteverify](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)
- Both existing limiter calls pass strings. Cloudflare's native binding and the installed Workers types require an object argument, `limit({ key })`. An isolated Miniflare probe rejected the string with `invalid rate limit options` and returned two allowed results followed by a denied result when given a valid object and a two-request limit. Use the provider type and update both calls before enabling the bindings through Wrangler's `[[ratelimits]]` configuration. The historical deployment has no limiter bindings enabled. [Cloudflare Rate Limiting API](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)
- The browser says “20 MB” and the code accepts 20 MiB (20,971,520 bytes). That file takes 27,962,028 Base64 bytes before the message and MIME overhead. Confirm the institutional mailbox and gateway limit before finalizing the advertised cap or display unit. Resend documents a 40 MB encoded message limit. [Resend attachments](https://resend.com/docs/dashboard/emails/attachments)
- Prove the near-limit Worker path under the actual Cloudflare plan before setting the final cap. The Workers Free plan limit is 10 ms of CPU per request and 128 MB of memory. Local tests cannot establish that production runtime budget. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/)
- Verify Worker access and provider log/retention settings without tailing applicant traffic. The source emits coarse event fields and passes the normalized email to the optional limiter. Resend and the receiving mail system process and may retain submissions and PDFs. Store redacted evidence only.
